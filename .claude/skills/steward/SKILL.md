# このリポジトリでのPR運用ルール

- 現時点でこのリポジトリにはCI(GitHub Actions等)が設定されていない。「CI red」の判定はチェックランが実際に存在する場合のみ適用し、チェックランが0件のときは「CIはグリーン(該当なし)」として扱ってよい。
- **`main`ブランチはGitHub Pagesの公開元であり、マージ=即本番反映**。これが他リポジトリとの最大の違い。そのため:
  - `main`への直接pushは行わない。必ずPR経由でマージする。
  - マージ前に、計算ロジック(`script.js`の`compute()`)に影響する変更が無いか、あるならその変更が意図した挙動かを本文で明確に説明する。
  - UIの見た目に関わる変更は、可能な範囲で「何がどう変わるか」をPR本文に書く(スクリーンショットが撮れる場合は添付する)。
- マージ方式はマージコミット(merge commit)を基本とする。フォースプッシュや履歴の書き換えは行わない。
- リポジトリオーナー(hanahanaburichika5529-debug)が実質的な唯一の開発者兼レビュアーであるため、レビュースレッドが無い状態は「対応不要」であって「レビュー待ち」ではない。
- コミットメッセージ・PR本文には attribution フッター(Co-Authored-By: Claude / Claude-Session リンク、PRなら🤖 Generated with Claude Code)を必ず付ける。
- このツールはGoogle OAuthクライアントID・アクセストークンなどを扱うが、いずれもユーザーのブラウザ側(localStorage)にのみ保存される設計。コード中に実際のクライアントIDやトークンをハードコードするようなPRは、意図的であっても必ず確認を挟む。
- 定期チェックイン(check-in)は約1時間おきを基本とする。状態に変化がなければサイレントに次のチェックインを再設定する。
